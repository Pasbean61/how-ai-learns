How the AI learns
— the technical version.

A website is built with HTML for the skeleton, CSS for the look, and GitHub to put it online. Machine learning has a recipe too. This guide walks through it step by step: what people actually do, which tools they use, and what is happening inside the computer. Every demo on this page really trains, live in your browser.

00 — The analogy

Building a website vs. training a model

The two jobs have the same overall shape. They differ in one important place. Click any row to compare.

🌐 Building a website 🧠 Training an ML model

The one real difference

When you build a website, you write every rule yourself: “this button is blue, 16px, centred”. In machine learning, you don’t write the rules. You write a learning procedure and give it examples, and the computer works out the rules on its own. Those rules are stored as millions (or billions) of numbers called parameters or weights.

01 — The big idea, in one loop

Learning = guess, measure the error, nudge, repeat

Every modern AI system learns with the same four-beat loop, from a spam filter to ChatGPT or Claude. Hover over each beat.

θ ← θ − η · ∇L “move the numbers a little bit
in the direction that reduces the error”
θtheta: all the model’s adjustable numbers (weights and biases).
Lloss: a single number saying how wrong the model is right now.
∇Lgradient: for every weight, which direction makes the loss go up, and how steeply.
ηeta, the learning rate: how big a step to take each time.

02 — The process, step by step

The 7 steps of a real ML project

This is the workflow a data scientist or ML engineer follows. Training (step 5) gets all the attention, but in real projects most of the time goes into steps 1, 2 and 6.

  2. 2Collect & prepare data
  3. 3Choose a model
  4. 4Define the loss

  6. 6Evaluate

1

Frame the problem

Before any code, decide what goes in, what should come out, and how you will know it worked. The kind of output decides the kind of ML you need:

  • Classification: pick a category (spam / not spam, cat / dog).
  • Regression: predict a number (house price, tomorrow’s temperature).
  • Clustering: find groups with no labels given (customer segments).
  • Generation: produce new text, images or audio (ChatGPT, Claude, Midjourney).

2

Collect & prepare the data

Data is the raw material. Each row is one example. The input columns are called features, and the answer you want to predict is the label (or target). Preparing data means removing errors and duplicates, filling in missing values, turning text and categories into numbers, and scaling features so they sit in similar ranges.

Data leakage is the classic beginner mistake: information from the test set sneaks into training (for example, you scale using the average of all the data). The model then looks brilliant in testing and fails in real life.

3

Choose a model (the “skeleton”)

The model is a mathematical function with adjustable knobs, its parameters. Choosing a model is like writing the HTML skeleton: it fixes the shape of what can be learned, while training later fills in the details. The simplest building block of a neural network is a single neuron: multiply each input by a weight, add them up with a bias, then pass the total through a “squash” function.

Accuracy—

A neuron can only draw one straight boundary. To learn curvy boundaries, we stack many neurons in layers. That stack is a neural network, and you will train one in Step 5.

Models range from tiny to enormous

The same idea scales from 2 parameters to hundreds of billions. Bars use a log scale: each grid line is 1,000× more.

4

Define the loss (the scorecard)

To improve, the model needs one number that says how wrong it is. That number is the loss. For predicting numbers, the standard choice is Mean Squared Error: take each prediction’s error, square it, and average. Squaring makes big mistakes count a lot more than small ones. You can literally see it as squares.

Demo 5

You are the optimiser

Move the line and make the squares as small as possible
MSE loss—

With 2 knobs you can do this by hand. GPT-3 has 175 billion knobs [9]. That is why we need an automatic method: gradient descent.

For choosing between categories, models use cross-entropy loss instead: if the model gave the correct answer probability p, the loss is −log(p). Being confident and right costs almost nothing, and being confident and wrong costs a lot. Language models use exactly this loss, one word at a time (see the LLM section).

5

Train: gradient descent + backpropagation

Picture the loss as a landscape. Every possible setting of the weights is a location, and the height is the loss. Training means walking downhill. At each step the gradient tells us which way is uphill, so we step the opposite way. The size of the step is the learning rate, and it is the most important setting in all of deep learning.

Backpropagation: how the gradient is calculated

For a network with millions of weights, how do we know which way to nudge each one? Backpropagation [6] applies the chain rule from calculus backwards through the computation. The forward pass computes the prediction. The backward pass passes “blame” from the loss back to every weight. Try it on the smallest possible network: one input, one weight, one bias.

The training loop: epochs and mini-batches

Real training repeats the loop thousands to millions of times. Instead of using all the data in each step, we use a small random mini-batch (say 32 examples). This is faster and the randomness helps. One full pass through the training data is an epoch. Modern optimisers such as Adam [7] adapt the step size for every weight automatically.

This is what training looks like in PyTorch. Every line maps to a beat of the loop above:

# one epoch = one pass over the data
for epoch in range(100):
  for X, y in batches(train_data, size=32):
    pred = model(X)          # 1 predict
    loss = loss_fn(pred, y)  # 2 measure
    optimizer.zero_grad()
    loss.backward()          # 3 gradient (backprop)
    optimizer.step()         # 4 update weights

The neural-network lab

Now everything together. This is a real neural network with layers of neurons, trained by backpropagation and Adam, entirely in your browser. A single neuron can only draw a straight line (Demo 4). Watch what a few layers can do.

  • Spiral, 1 hidden layer: stuck near 50%. The model is too simple, so it underfits.
  • Spiral, 2 layers × 6: after a few hundred epochs it climbs to about 95%.
  • Spiral, 3 layers × 8: the train loss drops to almost 0 while the test loss stays high. This is overfitting, previewing Step 6.
  • Learning rate 0.1+: the loss curve becomes jumpy, the same effect you saw in Demo 6.

6

Evaluate: did it learn, or just memorise?

A model that is perfect on its training data might simply have memorised it. The real question is how it does on data it has never seen. Two failure modes:

  • Underfitting: the model is too simple to capture the pattern. It is bad on training and test data.
  • Overfitting: the model is so flexible that it learns the noise. It is great on training data and bad on test data.

Fixes for overfitting include more data, simpler models, regularisation (penalising large weights), dropout [12], and early stopping (stop training when validation loss starts to rise. Watch the test curve in Demo 8).

Accuracy is not the only score

Suppose a spam filter gives every email a “spam score” from 0 to 1. Where you set the cut-off changes the kind of mistakes it makes. Precision asks: of the emails flagged as spam, how many really were? Recall asks: of all the real spam, how much did we catch?

7

Deploy & monitor

After training, the model is just a file of numbers, for example model.pt or model.safetensors. To make it useful you wrap it in an app or an API, which is like publishing your website on GitHub Pages. Then you keep watching it, because the world changes and a model trained on last year’s data slowly goes stale. This is called data drift.

Running a trained model to get answers is called inference. Inference is cheap compared with training: training a large language model can take thousands of GPUs for weeks, while answering one question takes a fraction of a second.

03 — Scaling up

So how do ChatGPT and Claude learn?

The same 7 steps and the same loop, at an enormous scale. A large language model (LLM) is trained in stages.

Stage 1

Pre-training

Task: predict the next word (more precisely, the next token) across a huge amount of text. Meta’s Llama 3 was trained on about 15 trillion tokens [16].

Model: a Transformer [8], a neural network that uses “attention” to decide which earlier words matter for the next one.

Loss: cross-entropy on the correct next token. Training: gradient descent and backprop, exactly as in Step 5.

Result: a model that knows a lot about language and the world, but just continues text.

Stage 2

Supervised fine-tuning

Continue training on many curated examples of (instruction → good answer), written or checked by people. Same loss and same loop, but on much smaller, higher-quality data.

Result: a model that follows instructions and answers like an assistant.

Stage 3

Learning from feedback

People (or a written set of principles) compare answers and rank which is better. A reward model learns these preferences, and reinforcement learning pushes the LLM towards preferred answers. This is RLHF [10]. Anthropic’s Constitutional AI uses AI feedback guided by written principles [11].

Result: a more helpful, honest and harmless assistant.

This is a bigram model. It only counts which word follows which, so it is millions of times simpler than a real LLM. A real LLM looks at thousands of previous tokens, not just one. It also learns its probabilities with billions of weights through gradient descent instead of counting. The training goal is the same: make the true next word more probable.

Scale is a big part of the story

Researchers found that loss falls smoothly and predictably as you increase model size, data and compute (“scaling laws” [13]). DeepMind’s Chinchilla study showed that data must grow along with model size. Their 70-billion-parameter model trained on 1.4 trillion tokens outperformed much larger models [14].

04 — Your turn

How can someone actually do it? Three routes

Like websites, there is a no-code route, a hand-coded route, and the “vibe coding” route where an AI writes the code for you. All three follow the same 7 steps.

Google Teachable Machine

Train an image, sound or pose classifier in your browser with no code [17]. It is the “website builder” of ML, and a great way to feel the 7 steps.

  1. Frame: open teachablemachine.withgoogle.com → Image Project → Standard. Pick 2–3 classes, e.g. 👍 / 👎 / ✋.
  2. Data: record 100+ webcam images per class. Vary lighting, angle and background, otherwise the model learns the background instead of your hand.
  3. Model: already chosen for you (a pretrained image network that gets fine-tuned. This is called transfer learning).
  4. Train: click Train Model. Open Advanced to see epochs, batch size and learning rate, the same knobs as this guide.
  5. Evaluate: use Preview with new poses, a friend’s hand, or a different room. Where does it fail?
  6. Deploy: Export Model to get a shareable link or TensorFlow.js code for a website.

Why it works with so little data

The model started out already trained on millions of photos. You only fine-tune its last layer to your classes. This is the same idea as Stage 2 of an LLM: start from a pretrained model and adapt it.

Other no-code / low-code tools

Hugging Face AutoTrain [21] (upload a CSV or images and it trains and compares models), and fine-tuning interfaces from cloud providers.
